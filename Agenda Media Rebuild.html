Agenda media rebuild

Media moves out of songs and themes and into the agenda. You drop files into the sidebar, they land safely in the synced media folder (or in Nextcloud from the web), and images, videos and audio become items of their own, including backgrounds. A group in the agenda then decides how its media plays together, and groups can be reused from a library.

Revision 6: review of the built phases — an entry opens without going live, media can be added straight from the group menu, the plan gaps are listed with what was closed. Revision 5: themes on agenda groups instead of songs, Nextcloud sign-in like the desktop client, previews without a second screen, per-window settings dropped. Revision 4:screen sets for groups that usually show the same thing, and slideshows as their own items so each screen group can run its own. Revision 3:screen groups are the only target and windows stay local placements; Nextcloud is web-only and stored in the browser; several backgrounds per group with switching and a leave behaviour; theme keeps a colour only; library includes past shows.

Fixed already: song editor text view

The lyric editor is reused for every block tab and copied the text only once. So in text mode, switching tabs kept the previous block's text. The text is now derived from the block you opened. Line view and text view always agree. Typecheck is clean.

What stays, what goes

  • Stays: themes for text (fonts, colours, positions), a plain background colour per theme, stage monitor layouts and overlays, songs, Bible verses, set lists, the operator view structure.
  • Goes: background images and videos in themes, the background library and background track, song-remembered backgrounds and media cues, themes set on songs or single items. The agenda takes over all of them.
Review · 23 Sep 2026

What the review changed, and what is still missing

All ten phases were in the code, typecheck and tests clean. Going through the app as an operator showed one flow problem that made everything else harder, a handful of plan items without UI, and one bug.

Built: look at an entry without putting it on screen

Before, the middle column only ever showed the live entry. With the default double-click setting, a single click in the agenda did nothing. To look at a video's settings in Prepare you had to put it on the screens.

  • Click an agenda entry: it opens in the middle column, the preview and the inspector. Nothing reaches the screens. The row gets a blue edge; the live row stays red.
  • A bar above it says Not on screen and names what is on screen, with Back to live and Go live (Enter).
  • Double-click the row, click a slide, or press Enter: it goes live, and the view follows the screens again.
  • In Live with “Go live with: click”, a single click still goes live as before.

Built: fewer clicks to add media

  • A group's Add item menu now offers Add background (added straight as Background) and Add slideshow, each with a one-line explanation. Add media mentions that files can be dropped onto the agenda.
  • A media entry you add opens by itself, so its role, screens and framing are visible without another click.
  • Fixed: a slideshow created empty never showed its images once they were added.
  • “Start playing when opened” now reads “Play as soon as it is on screen”, because “opened” means something else now.

Built: plan items that had no UI

  • A different file per screen (part 3, versions): the framing rows have a file menu with Other file…, so LED left and LED right can show the two halves of a panorama. The outputs already supported it.
  • ◀ ▶ for slideshows in the layer bar (part 3): each running slideshow steps on its own, like in the mockup.
  • Duplicate group on screen groups (part 3, screen sets): a second group with the same settings in one click.

Still missing from the plan

  • Audio on the timeline (part 2): playback tracks cannot use sections, loops or follow the lyrics yet. Audio has its own player and is not on the shared transport. This is the largest gap.
  • Preview size per screen group (part 3d): without an open window the preview draws 16:9, and the media card uses one aspect setting for everything.
  • Nextcloud thumbnails in the web media browser (part 1).
  • Trim in/out per version (data model): sections and pauses in the timeline cover most uses today.

How a file is referenced

  • Always a path relative to the media folder with forward slashes, e.g. Worship/2026/intro-clouds.mp4. Absolute paths are never stored, so every synced computer resolves the same file.
  • Every media item shows a missing file warning if the path is not found, with Find in media folder to relink it.
  • The desktop app copies through the existing import in the media server.

Web version only: Nextcloud

A browser cannot see a dropped file's location or write into a local folder. With a Nextcloud connection it can do the same things as the desktop app. The desktop app does not use it: there the Nextcloud client syncs the media folder, which also works offline.

  • Connect once per browser, exactly like the Nextcloud desktop client: Settings opens Nextcloud's login page (Login Flow v2). When Nextcloud signs in through the same identity provider as the presenter, you are already logged in and only click Grant access. Nextcloud then hands out an app password for this browser.
  • Permissions come from Nextcloud: the connection acts as your Nextcloud user, so only folders shared with you are visible and writable. Access is managed where it already is.
  • The app password is stored only in this browser, never in the database, and shows up in Nextcloud under Devices & sessions, where it can be revoked.
  • Choose the media root in Nextcloud, e.g. /Gemeinde/Presenter-Media. Desktop computers sync that same folder with the Nextcloud client, so relative paths match everywhere.
  • Drop: the same folder picker, browsing Nextcloud. The file is uploaded in small chunks, so large videos work with any upload limit. A file already there with the same name and size is reused.
  • Media browser in the web version browses Nextcloud too (thumbnails from Nextcloud's previews).
  • Without Nextcloud the web version matches a dropped file by name in the media folder and explains when nothing matches.

Part 1b

Screen groups are the only target

Everything that decides what a screen shows lives on its screen group, which is stored in the database and is the same on every device. A window only says where it is and which group it belongs to, and that stays on the computer that opens it. Nothing targets a single window any more.

What moves where

  • Screen group (database, all devices): kind, layers, stage layout, languages, display mode (normal or stream lines), transparent output, and every media, background and stage overlay assignment.
  • Window (this computer only): display, size and position, fullscreen, frameless, always on top, hide mouse, and its group. A window without a group is not possible: new windows join the first Audience group.
  • Removed: per-window theme and item styles by window name, per-window languages and hide flags, output roles for media cues, stage layers picked per window.
  • Two windows that need different content get two groups. A panorama over two LED screens becomes “LED left” and “LED right”, each with its own crop.
  • No computer profiles and nothing about windows in the database. Each computer keeps a copy of the groups, so it can open its windows when the server cannot be reached.

Part 1c

Themes belong to the agenda group

Songs become pure content: text, languages, arrangements. How they look is decided by the agenda group they are in. This makes things simpler, not more complicated, because there is exactly one place to look when a slide looks wrong.

Where the look comes from

  • Agenda group theme → otherwise the show theme → otherwise the account default theme. Three levels, all in the agenda.
  • Screens that need a different look (a stream lower third, a smaller text on the LED wall) use the theme's existing screen group variants, so the group's theme adapts per screen by itself. Screen groups do not pick a theme of their own.
  • Removed: the theme on a song, the theme on a single agenda item, and “use the show's look” on items. The song editor loses its look section.
  • A song that must look different (e.g. a hymn with long lines) goes into its own small agenda group with another theme. That keeps the exception visible in the agenda instead of hidden in the song.
  • The group header shows its theme as a chip; one click changes it for every item in the group.
  • Library entries keep their group's theme, so a reused worship set keeps its look.

Part 2

Audio items

Played only on the operator computer, never sent to presentation windows. Useful for pads, walk-in music and playback tracks.

Controls

  • Play, pause, stop, seek, volume, loop.
  • Fade out (e.g. 3 s) as its own button, because stopping a pad mid-note sounds bad.
  • Keeps playing while you move through songs until you stop it, like a pad under the whole worship set.
  • Visible in the layer bar's Media row, so it can be stopped from anywhere.

Shares the video playback engine

Audio uses the same transport as videos (sections, loops, pause points, waveform). A playback track can use the timeline editor and follow the lyrics exactly like a video. Groups can play audio and video together.

Versions (arrangements) of a media item

  • Like song orders: a named version, chosen per agenda item.
  • A version has its own in/out trim, timeline (sections, loops, pauses), lyric mapping and optionally different files per screen (panorama left/right).
  • When a song's arrangement changes, the mapping asks for review, as today.

Belonging together through the group

  • A video follows a song only if both are in the same group. With several songs in the group you pick which one.
  • Starting a song whose group has a mapped video can start that video on the first slide (a setting on the group).
  • Screens are chosen only by screen group (Audience, Stage, LED left, …), any number at once.

Several screen groups at once, and screen sets

Every item can already show on any number of screen groups. To keep a split LED wall easy, groups that usually show the same thing can be bundled into a screen set, e.g. “LED wall” = LED left + LED right.

How screen sets work

  • A screen set is only a named shortcut, managed next to the screen groups. It appears as one chip in every “Show on” picker and turns all its groups on or off together.
  • After choosing the set, each group still gets its own row under Per screen, so LED left and LED right can crop the halves of one panorama, or both show the whole picture.
  • New groups in the set start with Same as LED left framing, so the usual case needs no extra clicks.
  • To show something on only one half, open the set chip and untick the other group.
  • Screen group settings themselves (theme, languages) are not shared; Duplicate group makes a second group with the same settings in one step.

Slideshows are their own items

  • A slideshow item holds a list of images with duration, cut or fade, and repeat, and has its own Show on and role (content or background), like a video.
  • Two slideshows in the same agenda group can therefore run side by side on different screen groups: announcements on LED left, photos of the youth camp on LED right.
  • Dropping several images at once offers Create slideshow; images can be reordered by drag and drop inside it.
  • Timing can be set per slideshow; a later extension could add per-image durations or captions.
  • This replaces the group-wide slideshow switch from revision 3.

Part 3b

Backgrounds come from the agenda

Themes no longer hold background images or videos. An image or video item gets a role: Content fills the screen as the item itself, Background sits behind the lyrics of its group.

How a background item behaves

  • A group can hold any number of background items. The first one starts when the group is entered; the others wait to be switched to.
  • Only one background runs at a time per screen group. Switching crossfades (cut or fade, set per group).
  • It shows only on screen groups that show backgrounds; Stage and Stream keep their own switches.
  • The existing Hide background button and shortcut hide it without stopping it, so a video keeps its place.
  • When the group is left the group decides: keep it running, fade it out, or hide it immediately. A kept background runs until another one starts or you hide it.
  • A background video loops by default and can follow the song's sections through its timeline, which replaces the old “background per section” setting.
  • A slideshow item with the Background role steps through its images behind the lyrics.
  • Switching is per screen group: a background that shows only on LED left leaves the Audience background untouched.
  • With no background at all, a screen shows the theme's colour.

How reuse works

  • Save to library on any group in the agenda. The entry is a copy, so later changes in a show never change the library or old shows.
  • Update library entry from a changed group, with confirmation (like today's “Save to song”).
  • Past shows count too: the library also lists groups from previous shows, marked “from 06 Sep”, without saving them explicitly.
  • Suggestions: adding a song to a show offers the media items it had in its group last time (“Clouds loop was used with this song, add it?”).
  • Missing files in an entry are flagged before it is added.

How previews work

  • Preview panel in Prepare mode: whatever you select in the agenda is drawn exactly as a screen group would show it. Tabs switch between screen groups, arrow keys step through slides, nothing goes live.
  • Media: videos, audio and slideshows play inside the preview with their own clock, muted by default, with scrubbing, loops and pauses. The live outputs are never touched, like today's audition in the cue editor.
  • Pop out opens the preview in a resizable window on the same screen, handy beside the agenda on a laptop.
  • Hover previews: media items and library entries show a short muted preview when hovered, as the media browser already does.
  • Editors use it too: the theme editor, song editor and media item editor show the same preview, so a theme change is judged on real lyrics and real backgrounds.
  • The aspect ratio comes from an open window of that group on this computer, otherwise from a preview size setting on the screen group (default 16:9).
Part 4

Edit the whole song as text

A Text tab next to the info tab in the song editor. It holds the entire song. Your idea of Markdown-style headings works well: they cannot clash with lyric lines, and --- already means page break. A how-to sits beside the text, so nobody has to remember the syntax.

# Verse 1 Großer Gott, wir loben dich, [en] Holy God, we praise thy name, Herr, wir preisen deine Stärke. --- Vor dir neigt die Erde sich und bewundert deine Werke. # Chorus Wie du warst vor aller Zeit, so bleibst du in Ewigkeit.
How it works
# ChorusStarts a block. Everything below belongs to it until the next #. ---New slide inside the block. [en] textTranslation of the line above, in English. empty lineIgnored, use it for spacing.
Good to know
  • Renaming a heading renames the block in every order.
  • Removing a heading asks first if orders use it.
  • Orders are edited below, not in the text.
# Block---[en]insert at cursor
4 blocks · 9 slides · languages de, en
Beside the text on wide screens, collapsible below it on phones. The status line checks the text live and names the line of any error, e.g. “Line 14: Chorus appears twice”.

Rules

  • # Name starts a block; the name is the rest of the line.
  • Text before the first heading goes into a block named with your default verse name.
  • A duplicate heading shows an error and nothing is applied until it is fixed.
  • Renaming a heading renames the block and updates every order. Renames are detected when the blocks keep their position.
  • Removing a heading removes that block from orders after a confirmation listing the orders it was used in.
  • Orders stay in the order editor below the text; they are not written into the text.
  • Can be built right away, independent of the media work.
